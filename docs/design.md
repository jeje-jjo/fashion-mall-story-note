# 상황별 추천 설계안 (검토용)

작성: 2026-11-06 · 상태: **제제 검토 대기**
근거: 공략 사이트 메커니즘 페이지·옷/시설/코디 세트/배틀/콘테스트 표(Firestore `ref/*`). 가이드는 참고만.

## 1. 공통 원칙
- **탭을 옮기지 않는다.** 어떤 화면에서든 옷·시설·손님·배틀 이름을 누르면 **아래에서 올라오는 시트**로 상세가 열리고, 닫으면 원래 자리로 돌아온다.
- **추천은 이유와 함께 보여 준다.** 점수만 주지 않고 `계절 ✓ · 세트 완성 · 상하 궁합 +1 · 매력 520`처럼 근거 태그를 붙인다.
  - 사이트도 계산식이 "추정"이라고 밝힌다. 그래서 확률(%)을 지어내지 않고, **순위와 근거**만 보여 준다.
- **결과 목록에서 바로 처리한다.** 목록의 옷을 탭하면 완료 체크, 마네킹·전투 슬롯에 넣기, 핀 고정을 그 자리에서 한다.
- 입력은 칩이나 토글로 고르게 한다. 타이핑은 검색할 때만 한다.

## 2. "지금 상태" (헤더 한 줄, 모든 추천이 같이 씀)
| 값 | 입력 방식 | 쓰는 곳 |
|---|---|---|
| 회차 · 몇 년 차 · 몇 월 | 헤더 pill에서 ± | 콘테스트·리셋 주기 |
| 지금 계절 | 월에서 자동으로 정하고, 다르면 pill로 바꾼다 | 마네킹, 다음에 만들 옷 |
| 유행색 | 색 칩에서 고른다(게임 화면을 보고) | 마네킹, 판매 |

- Firestore `runs/rN/ui/now`에 저장하고 기기 간에 동기화한다.
- 월 → 계절 대응은 사이트에 표가 없다. 처음에는 제제가 정하고, 게임에서 확인한 값으로 고정한다.

## 3. 상황별 추천

### ① 마네킹 플래너 (의류 탭 → [마네킹] 세그먼트, 메인에도 요약)
- **입력**: 마네킹 칸 1~5(개수는 바꿀 수 있음). 칸마다 마네킹 장르(내추럴~서브컬처 7종 = 시설 46~52)와 계절(기본은 지금 계절).
- **후보**: **완료한 옷만** 쓴다. 상의+하의 또는 셋업에 아우터·액세서리를 더한 조합이다.
- **점수 근거(사이트 메커니즘)**

  | 요소 | 계산 | 출처 |
  |---|---|---|
  | 계절 궁합 | 옷마다 맞음 +1 / 보통 0 / 반대 −1(여름↔겨울) | 사이트 "옷 계절과 목표 계절의 궁합" |
  | 상하 궁합 | 잘 어울림 +1 / 안 어울림 −1, 셋업은 항상 +1 | 사이트 "상·하의 궁합", 옷 표 goodWith·badWith |
  | 코디 세트 | 구성 옷이 모두 들어가면 "세트 완성" | 사이트 코디 세트 207개 |
  | 장르 | 마네킹 장르와 옷 장르가 같은지(세부 장르 스타일 점수) | 옷 표 genre·styleScores |
  | 매력(인기)·품질 | 제제가 기록한 값을 먼저 쓰고, 없으면 사이트 기본값 | 노트 기록, 사이트 |
  | 유행색 | 지금 유행색이면 표시 | 사이트 "유행 상태" |

- **정렬**: 계절에서 −1이 있는 조합은 뺀다 → 세트 완성 → 궁합 합 → 매력+품질 순서로 정렬한다.
- **결과**: 칸마다 상위 5개를 보여 준다. 다른 칸에 이미 쓴 옷은 흐리게 표시한다.
- **"이 코디로 세움"**: 누르면 Firestore `runs/rN/mannequins/m1..5`에 저장한다. 다음에 계절이 바뀌면 "계절 안 맞음" 경고를 띄운다.

### ② 다음에 만들 옷 (의류 탭 [미완료] 맨 위, 메인 "남은 할 일")
- **입력**: 가진 옷본·재료·옵션을 칩으로 체크한다(N12). 저장은 `runs/rN/ui/recipes`.
- **후보**: 지금 재료로 **만들 수 있는 미완료 옷**만 고른다.
- **우선순위 이유 태그**
  - `세트 1벌 남음`: 이 옷만 만들면 코디 세트가 완성된다.
  - `손님 요청`: 열려 있는 코디 요청에 들어간 옷
  - `전투 조건`: 아직 못 이긴 배틀의 의류 조건에 맞는 옷
  - `계절 ✓`: 지금 계절에 맞는 옷
  - `패션 체크 보상` / `특수 옵션`
- **"못 만드는 옷"**: 접어 둔 목록에 넣고, 무엇이 없는지 표시한다. 예: `재료 슬릿넥 없음`.

### ③ 전투 준비 (기록 탭 [전투], 배틀 상세 시트)
- **배틀 하나를 열면 한 화면에 보여 줄 것**
  - 요청 설명, 의류 조건, 상대 기준값 `value` = **품질 · 매력 · 능력치**(코디 합계), 참가비, 보상
- **추천**: 완료한 옷 중 조건(장르·스타일·베이스·태그)에 맞는 옷을 슬롯별로 보여 준다.
  - 고른 코디의 품질 합과 매력 합을 상대 value와 나란히 보여 준다. 예: `품질 3,980 / 4,230 (−250)`
  - 능력치는 점원 값이라 제제가 입력한다.
- **기록**: 기존 기능 그대로다. 슬롯 저장, 시도 기록, ⚔️ 표시를 한다.

### ④ 콘테스트 (기록 탭 [콘테스트], 메인에 "올해 콘테스트")
- 사이트 콘테스트 20개의 **통과 점수와 보상만** 쓴다(제제 결정).
- 년도별 등급 표는 기존 그대로 두고, 칸마다 통과 점수와 보상 옵션을 보여 준다.
- 기존 점수 기록은 지우지 않고 그대로 보여 준다.

### ⑤ 패션 체크 준비 (기록 탭 [패션 체크], 시설 탭과 연결)
- 체크마다 보여 줄 것
  - 필요한 시설·대신 가능 시설과, 내가 지은 시설인지 여부
  - 평론가, 상금, 보상 옵션, 등장 조건
- **"지금 도전 가능"**을 맨 위에 둔다. 필요한 시설이 다 있는 체크다.

### ⑥ 코디 (코디 탭 [손님 요청 | 코디 세트])
- **손님 요청**: 기존 기능(대성공 기준)을 그대로 둔다. 요청한 옷마다 완료 여부를 표시하고, 탭하면 옷 시트가 열린다.
- **코디 세트**: 207개를 세부 장르별로 묶는다. 만든 옷 ✓, 진행률, `1벌 남음` 필터를 둔다.

### ⑦ 메인 "오늘 할 일" (한 화면 요약)
- 세트 1벌 남음, 만들 수 있는 미완료 옷, 지금 도전 가능한 패션 체크, 올해 콘테스트, 계절이 안 맞는 마네킹, 게임에서 확인할 것을 보여 준다.
- 항목마다 탭하면 시트가 열린다. 탭은 옮기지 않는다.

## 4. 저장 위치 (Firestore, 본인만)
```
ref/*                         기준 데이터(사이트 번호)
runs/rN/clo/{옷id}            완료 체크 등(기존 노트 구조를 이어받음)
runs/rN/ui/now                지금 상태(년·월·계절·유행색)
runs/rN/ui/recipes            가진 옷본·재료·옵션
runs/rN/mannequins/m1..m5     세운 마네킹 코디
runs/rN/trophies, missions    회차별 체크(이전 회차 그대로 보존)
ui/*                          회차와 무관한 설정(칩 순서, 배치, 팔레트)
```

## 5. 정해 줄 것
1. **월 → 계절**: 게임에서 몇 월이 여름·겨울인지. 모르면 처음엔 계절을 직접 고르게 만든다.
2. **마네킹 코디 구성**: 아우터·액세서리까지 넣는지, 상의+하의(셋업)만 볼지.
3. **매력·품질 값**: 제제가 기록한 값(10-30 영상으로 확인한 427벌)이 있으면 그 값을 우선할지.
4. 위 ①~⑦ 중 먼저 만들 순서. 제안은 ⑥ 코디 → ② 다음에 만들 옷 → ① 마네킹 → ③ 전투 → ⑦ 메인이다.

## 6. 데이터에서 같이 고칠 것
- 옷 계절 값 `봄&가을` 2벌 → `봄·가을`로 맞춘다(표기 통일).
- 상하 궁합 목록이 사이트에서 8개까지만 보이고 나머지가 `+3`처럼 잘려 있다. 받은 페이지 원문에 전체 목록이 있는지 확인해서 채운다.
- 사이트의 "판매 예측" 도구(sales.html)에 판매 계산 방식이 들어 있을 수 있다. 필요하면 한 쪽만 더 받아서 확인한다.
