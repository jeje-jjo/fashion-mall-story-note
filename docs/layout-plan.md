## 2. 지금 화면의 문제 (휴대폰 기준)

1. **모든 탭 위에 같은 설정이 반복된다.** 리셋 주기, 개량 옵션 찾기, 자동·핸드폰·PC 모드, 테마, 메인 색상이 첫 화면의 약 40%를 차지한다. 이 중 화면 설정은 거의 바꾸지 않는다.
2. **같은 기능이 여러 곳에 흩어져 있다.**
   - 개량 옵션: 헤더 빠른 보기, 메인 카드, 기록 탭 [개량 옵션] 세 곳
   - 리셋 주기: 헤더 빠른 보기, 메인 카드 두 곳
3. **게임 이벤트가 여기저기 나뉘어 있다.** 패션 체크·모델 체크는 시설 탭, 챌린지 배틀은 의류 탭, 콘테스트·목표는 기록 탭에 있다. 게임에서 "패션 체크 떴다"는 순간에 어디로 가야 할지 기억해야 한다.
4. **"기록" 탭이 잡동사니 서랍이다.** 콘테스트·목표(게임 진행), 자료·개량 옵션·배치(참고 도구), 관리(가져오기·새 회차·변경 기록)가 한 줄 세그먼트 6칸에 섞여 있다.
5. **의류 탭에서 목록까지 너무 멀다.** 다음에 만들 옷, 장르·옷본·재료·옵션 필터 4줄과 단일/다중·⋯ 버튼, 전체 접기·펼치기·다중선택·저장·불러오기·순서 수정, 전투 줄을 다 지나야 옷이 나온다.
6. **메인에 카드가 너무 많다**(오늘 할 일, 남은 할 일, 리셋 주기, 개량 옵션, 최근, 태그 색 안내, 클리어 포인트, 회차 연계).

## 3. 제안 구조

### 3-1. 맨 위 (모든 탭 공통, 한 줄)

```
[회차 7 ▾]  탭 제목                [● 저장됨]  [⚙]
```
- 회차 칩을 누르면 진행 요약이 열린다(시설 %, 옷 %, 세트 완성 수, 트로피). 지금 진행 막대가 하던 일이다.
- `⚙` 메뉴(시트): 화면 모드(자동·핸드폰·PC·패드), 테마, 메인 색상, 로그인 계정, 로그아웃.
- "지금 저장" 버튼은 저장 점을 누르면 실행한다(Firestore는 자동 저장이라 평소에는 안 씀).
- 스크롤하면 제목이 작아지고 탭 안 세그먼트(하위 탭)만 위에 붙는다.

### 3-2. 아래 탭 5개

| 탭 | 하위 탭 | 들어가는 것 | 지금 위치 |
|---|---|---|---|
| **홈** | - | 통합 검색, 오늘 할 일, 바로가기 칩(개량 옵션·리셋 주기·배치·자료), 최근 변경(되돌리기) | 메인 |
| **의류** | 옷 목록 · 만들 수 있는 옷 | 옷 목록(필터는 아래 시트), 다음에 만들 옷(가진 옷본·재료·옵션), 필요한 옵션 개수 | 의류 |
| **시설** | 시설 목록 · 아이템 넣기 | 시설 목록(장르·40P), "아이템 넣기"(아이템 고르면 넣을 시설과 일괄 넣기) | 시설 |
| **코디** | 손님 요청 · 코디 세트 · 마네킹 | 그대로 | 코디 |
| **도전** | 패션 체크 · 배틀 · 콘테스트 · 목표 | 게임에서 뜨는 이벤트를 한곳에. 사이트 기준값 먼저, 내 기록은 "기록 보기" | 시설(패션 체크), 의류(배틀), 기록(콘테스트·목표) |

**기록 탭은 없애고** 남은 것은 홈 바로가기와 ⚙ 옆 `≡ 도구` 시트로 옮긴다.

| 도구 시트 `≡` | 내용 | 지금 위치 |
|---|---|---|
| 개량 옵션 | 직원별·옵션별 표, 옵션 찾기 | 헤더·메인·기록 세 곳 → 한 곳 |
| 리셋 주기 | 호박·손님 월 메모 | 헤더·메인 → 한 곳 |
| 배치 연습 | 30×30 판, 추천 10, 내 배치 1~5 | 기록 |
| 계산기 | 클리어 포인트, 회차 연계 | 메인 |
| 자료 | 사이트 표 16개 | 기록 |
| 관리 | **기존 노트에서 가져오기**(주말 아이패드 이전용, 그대로 유지), 새 회차 시작, 번역 이름 수정, 시트에 반영할 변경, 최근 기록, 게임에서 확인할 것 | 기록 [관리] |
| 태그 색 안내 | 색 범례 | 메인 |

- 홈 바로가기 칩은 4개까지 고정한다. 기본은 개량 옵션, 리셋 주기, 계산기, 관리이고, 순서와 종류는 기기별로 localStorage에 둔다(Firestore 경로를 늘리지 않음).
- 탭 순서는 많이 쓰는 순서(홈 → 의류 → 시설 → 코디 → 도전)이다.

### 3-3. 탭 안 공통 틀 (휴대폰)

```
┌ 세그먼트(하위 탭) ─────────────┐   ← 스크롤해도 위에 붙음
│ 검색창            [필터 3 ▾]   │   ← 필터는 아래에서 올라오는 시트
│ 적용 중: 큐트 × · 미완료 × ...  │   ← 켠 필터만 칩으로, ×로 바로 끔
│ 12 / 84 완료                   │
├────────────────────────────────┤
│ ○ 옷 이름   태그 태그        › │   ← 왼쪽 동그라미 = 완료 체크(44px)
│ ○ ...                          │      줄 누르면 상세 시트
```
- 필터 시트 안에 지금 의류 탭의 장르·옷본·재료·옵션 칩, 단일·다중, 순서 수정, 선택 저장·불러오기를 그대로 넣는다(`ui/slots`, `ui/chiporder` 저장 경로 그대로).
- 옷·시설·손님 상세는 지금처럼 펼치는 대신 **아래 시트**로 연다(아이패드에서는 오른쪽 칸). 목록 위치가 흔들리지 않는다.
- 아이패드 가로(≥900px)는 왼쪽 레일 + 목록 + 상세 2단으로 한다.

## 5. 그대로 지킬 것
- 저장 경로·필드 전부(docs/progress.md, 드라이브 "Firestore 구조" 문서 2절). 화면만 바꾸고 읽고 쓰는 함수는 그대로 쓴다.
- 기록 [관리]의 "기존 노트에서 가져오기"는 **도구 시트 → 관리**로 옮겨도 같은 코드를 쓴다. 주말 이전 전에 옮긴다면 홈 바로가기에도 둔다.
- 예전 주소 `#rec`, `#log` 등은 새 위치로 넘긴다(`OLD_TAB` 방식).
- 디자인 톤: 뮤트 로즈, 파란 버튼 없음, 작은 입력창, pill 세그먼트.

## 6. 진행 순서 (제안)
1. 맨 위 한 줄 + ⚙ 설정 시트 + ≡ 도구 시트, 기록 탭 → 도전 탭 (메뉴 이동만, 기능 그대로)
2. 의류·시설 필터 시트, 적용 중 칩 줄
3. 상세를 아래 시트로(옷·시설·손님), 아이패드 2단
4. 4절 데이터 엮기
5. 디자인 다듬기(색·간격·아이콘), 휴대폰·아이패드 스크린샷 비교

## 7. 제제가 정할 것
1. 기록 탭을 없애고 **도전 탭 + 도구 시트**로 나누는 것이 괜찮은지
2. 아래 탭 순서: 많이 쓰는 순서(홈·의류·시설·코디·도전)로 할지, 지금 순서(홈·시설·의류·코디·…)를 유지할지
3. 상세를 펼치기 대신 **아래 시트**로 바꾸는 것(가장 큰 변화)
4. 1단계부터 바로 시작할지, 먼저 휴대폰 시안 이미지를 볼지

### 조정
1. 아래 시트 없음. 상세는 행 아래, 필터는 검색줄 아래, ⚙·최근 변경은 머리줄 아래로 펼침
2. 넓은 화면: 오른쪽 상세 칸 없이 폭 전체 사용. 목록 2~3열 카드, 펼친 카드는 한 줄 전체 폭 + 내용 4칸, 필터 4칸 한 줄
3. 아래 탭: 의류 · 시설 · 코디 · 도전 · 도구 (홈 없앰 제안)
4. 최근 변경 = 머리줄 🕘, 지금 저장 = 머리줄 버튼 유지
5. 도전 = 패션 체크(모델 체크 포함) · 배틀(다른 가게 직원 포함) · 콘테스트(출현 년도 맨 위). 목표는 뺌
6. 의류: 선택 저장 1·2·3은 필터 펼침 안, 다음에 만들 옷은 하위 탭(필요한 옵션 개수 맨 위), 추가옵션 메모는 펼친 옷 안
7. 시설: 이름 수정은 펼친 상세 안 연필로만
8. 안 봄 기능은 지우지 않고 도구 맨 아래 "잘 안 쓰는 것"에 접기
9. 기존 노트에서 가져오기는 도구 → 관리 (코드·저장 경로 그대로)
- 남은 결정(시안 2 페이지에서 고름): 홈 탭 없애기, 안 봄 기능 처리, 넓은 화면 목록 모양, 처음 탭, 다음 단계
