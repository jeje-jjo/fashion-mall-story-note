# 패션몰스토리 노트 v2 계획

작성: 2026-11-06 (claude.ai 대화에서 정리)

## 1. 구성

| 역할 | 선택 | 이유 |
|---|---|---|
| 화면 | Vite + React + TypeScript (정적 사이트) | 사용자 주력 스택. 깃허브 페이지에 무난하다. |
| 배포 | GitHub Pages + GitHub Actions | 공개로 써도 된다고 사용자가 확인함. 자동 배포. |
| 진행 데이터 | Firebase Firestore (서울 리전) | 기존 노트 저장 API가 Firestore 방식이라 옮기기 쉽다. 무료 플랜에서 일시정지가 없고, 오프라인 캐시가 있다. |
| 로그인 | Firebase Auth, 구글 로그인 | 본인 uid만 쓰기를 허용한다. |
| 기준 데이터 | 구글 시트 ↔ `src/data/*.json` (빌드에 포함) | 시트를 실시간 저장소로 쓰지 않는다(느리고 쓰기 제한이 있음). |

### 아이폰 사파리 주의
github.io 사이트와 Firebase 로그인 도메인(`*.firebaseapp.com`)이 달라서, 사파리에서 리다이렉트 로그인이 꼬일 수 있다.
- 로그인은 `signInWithPopup`을 기본으로 하고, 영구 로그인 유지를 켠다.
- 사파리 탭과 "홈 화면에 추가"로 연 앱 **둘 다** 실제 기기에서 로그인되는지 사용자에게 확인을 요청한다.
- 안 되면 Firebase Hosting으로도 배포해서 같은 도메인에서 로그인하는 방안을 사용자에게 제안한다.
- Firebase Auth의 승인 도메인에 `<계정>.github.io`를 추가한다.

## 3. 이름 규칙(확정)
- 장르 `포크로어`(포클로어 X), 전투 `고저스 챌린지`(어른 챌린지 X), 돈 단위 `G`.
- 기본 장르 7개는 내추럴, 쿨, 큐트, 성숙, 레트로, 하드, 서브컬쳐. 노트의 키는 `서브컬쳐`이고, 화면 표시는 서브컬처.
  - 공략 문서에는 `어른`이라고 적힌 곳이 있으니 게임 표기를 확인한다.
- 세부 장르 14개: 캐주얼, 스트리트, 파스텔, 엘리건트, US레트로, 록, 코스프레, 포크로어, 모드, 팝, 고저스, 80년대레트로, 오리지널리티, 사이버.
- 특수 옵션: 카모플라주, 폼폼, 자수, 레오파드(호피 X), 보타이, 스터드, 고블랭(고블랭직 X), 게리코튼, 하네스, 자수 패치(와펜 X), 크로스, 나사와 볼트.
  - 공략 문서는 "게리 코튼", "카무플라주", "너트와 볼트" 등 표기가 다르다. 노트 표기를 따른다.
- 재료: `스트레이트`(회차 표기 없음). `슬릿`과 `슬릿넥`은 다른 재료다.
- 사용자가 입력한 매장 이름이 시설 이름보다 우선이다.

## 4. 기존 노트 기능 (새 노트에 모두 포함)
자세한 내용은 docs/legacy_note_HANDOFF.md. 탭 구성은 메인, 시설, 의류, 코디, 기록이다.
- **시설**
  - 장르 필터, 우선개량(40P) 필터
  - 아이템 상성 ◎◯× 표시, 목록에서 바로 상성 좋음 항목 넣기(일부완료), 아이템 일괄 넣기
  - 패션 체크 번호 표시, 없는 매장 표시
- **의류**
  - 보기: 전체 옷, 추가옵션, 전투 추천, 코디 추천(겹쳐 고르기)과 미완료/완료
  - 장르, 옷본, 재료, 옵션 칩 필터(순서는 드래그로 바꿈)
  - 필요한 옵션 카운터, 특수 옵션, 전투 태그(실제로 입혔으면 ⚔️)
  - 옷 정보 수정
- **코디**: 손님별 요청, 손님 단위 완료, 열어 둔 손님 상태 동기화, 요청별 수정
- **기록**
  - 콘테스트: 년도별 등급과 점수, 통과 기준, 건너뛴 등급은 그해 입력 점수로 묻기
  - 배치: 30×30 판, 7장르, 끌어서 그리기, 이동/크기/장르 바꾸기, 추천 배치 10개, 내 배치 1~5 저장
  - 개량 옵션, 관리(로그)
- **전투**: 15개, 슬롯에 입힌 옷, 매력, 품질, 능력 수치, 시도 기록
- **패션 체크**: 39개, 필요 시설과 대신 가능 시설, 점수 기록
- **회차**: 회차마다 진행 경로를 따로 둔다(runs/rN). 회차를 초기화해도 추가옵션 메모는 넘긴다.
- **기타**: 라이트/다크와 로즈 톤 팔레트, 쉼표 숫자 입력(저장은 숫자만), 작은 입력창

사용자 디자인 취향:
- 깔끔하고 모던하게, 뮤트 로즈 계열. 파란 버튼은 싫어한다.
- 입력창은 작게, 휴대폰에서 줄이 어긋나지 않게.
- 헤더의 pill 세그먼트 같은 토글을 좋아한다.

## 6. 단계
1. **저장소**: 깃허브 공개 저장소를 만들고, 첫 커밋으로 이 압축 내용을 올린다. legacy 테스트가 통과하는지 확인한다.
2. **조사와 계획**
   - 공략 사이트 robots.txt와 페이지 구성을 천천히 살핀다.
   - reference 엑셀과 사이트 구조를 대조한다.
   - 수집 범위와 순서, 시트 탭 설계안을 사용자에게 보여 주고 확인받는다.
3. **수집**
   - tools/crawler로 수집하고 캐시한다.
   - 기존 노트 id와 매칭해서 매칭표를 만든다(애매한 것은 사용자 확인).
4. **시트**
   - 구글 시트를 만든다(사용자 계정, 인증 방식은 사용자와 상의).
   - tools/sheets로 시트 → `src/data/*.json`을 만든다.
5. **앱**
   - Vite + React + TS로 새 노트를 만든다. 기존 기능 → 새 데이터 화면 순서로 진행한다.
   - 휴대폰 화면부터 확인한다.
6. **Firebase**
   - 웹 앱을 등록하고 설정 값을 넣는다.
   - 보안 규칙(본인 uid만)을 작성하고 배포한다.
   - 승인 도메인을 추가한다.
7. **이전**
   - 기존 노트 저장소의 최신 백업을 사용자에게 요청한다(claude.ai 대화에서 만들 수 있음).
   - tools/migrate로 Firestore에 넣는다. 사용자가 확인한 다음에 한다.
8. **배포와 확인**
   - GitHub Actions로 Pages에 배포한다.
   - 맥, 아이폰, 아이패드에서 로그인과 동기화를 사용자가 직접 확인한다.
