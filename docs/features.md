- `L` = 기존 노트 기능(그대로 가져감), `N` = 새로 넣자는 기능.

## 4. 결정 (2026-11-06 제제)

### 화면 원칙: 페이지 이동을 최대한 줄인다
- 한 화면에서 "지금 하려는 일"에 필요한 정보를 모아 목록으로 준다. 탭을 오가며 맞춰 보게 만들지 않는다.
- 예: 마네킹 5개를 세운다 → 마네킹마다 계절을 고르면, 그 계절에 맞고 인기가 높으면서 코디 세트가 맞는 옷을 바로 목록으로 준다.
- 이런 "상황별 추천"은 사이트·공략의 진행·메커니즘을 Claude가 파악해서 설계한다. 고칠 점은 제제가 쓰면서 알려 준다.
- 상세 정보는 페이지 이동 대신 그 자리에서 펼치거나 아래에서 올라오는 시트로 보여 준다.

### 탭과 디자인
- 탭은 **5개**: 메인 / 시설 / 의류 / 코디 / 기록. 공략 내용(N24~N30)은 따로 탭을 두지 않고, 쓰이는 화면 안에 넣는다. 계산기·표는 기록 탭 안 세그먼트로 둔다.
- 디자인은 **기존 노트 디자인과 레이아웃을 그대로** 쓴다(시안 5종은 나중에 꾸밀 때 참고). 라이트/다크와 색 변경(팔레트)은 넣는다.

### 기능 조정
| 번호 | 결정 |
|---|---|
| N13 | **뺌.** 점원 유니폼은 필요 없음. 카이로군 2벌(426, 427)은 "게임에서 확인할 것"에 두고, 제제가 확인하면 그때 고친다. |
| N14 | **기본.** 기존 손님 요청(대성공 기준으로 제제가 넣어 둔 것)과 새 코디 세트를 **둘 다** 넣는다. |
| N18 | **뺌.** 배치는 지금 기능으로 충분하다(무거워지기만 함). |
| N23 | **기본으로 바꾸고 범위를 줄임.** 콘테스트는 사이트의 **통과 점수와 보상만** 있으면 된다. 기존에 점수를 직접 입력한 건 통과 점수를 몰라서였다. |
| N27 | 트로피·미션은 **회차마다 새로** 체크하고, **이전 회차 기록은 보존**한다(runs/rN 방식 그대로). |

### 배틀 value 숫자
- 챌린지 배틀 등의 `value 4230, 3173, 1830` = **(코디 합계) 품질, 매력, 능력치** 순서다.

### 데이터 확인 결정
- 코튼 팬츠: 사이트에 2벌이 있다. 노트 140 = 사이트 #136(갈색, 센터 프레스), 사이트 #144(파란, 벨트)는 새 옷으로 추가한다.
- 옵션이 노트 "(없음)"인데 사이트에 있는 칸(33, 42)은 제제가 나중에 게임에서 확인한다.
